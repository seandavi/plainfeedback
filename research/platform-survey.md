# Survey platform survey for CFDE event feedback (researched 2026-10-14)

Requirements recap: pre/post/follow-up waves linked by pseudonymous token (no PII); free-text + export; no cookies required; roles (admin / creator / viewer / anonymous); group-owner multi-tenant RBAC; self-host (Docker/Postgres, Python/uv preferred); API/export.

Evidence legend: GH = GitHub API queried 2026-10-14 (repo metadata/releases). "unverified" = not confirmed from a primary source in this pass (many vendor pages 403/404'd or were silent). Cookie behavior of respondent pages was NOT verified empirically for any tool; test with a browser/devtools before committing.

## 2. Key caveats (short)

- **LimeSurvey**: Closest mature self-hosted fit on anonymity+tokens, but the "Anonymized responses" switch severs the participant link, so linking requires non-anonymized mode with opaque tokens (and then token table is the pseudonym map). Groups are "experimental"; no group-owner delegation. PHP, not Python. API is JSON-RPC.
- **Formbricks**: Best modern UX/API, but exactly the feature you need (teams/roles) is AGPL-excluded Enterprise code; self-host stack is heavy (8 services in v6). Product aimed at in-app/product feedback.
- **SurveyJS**: Library is MIT and unopinionated; the Creator (form builder UI) costs per developer ($589+ Basic, annual renewal for updates). If creators are non-developers, Creator license counts developers, not end users (per README: "each software developer who works with the SurveyJS APIs"). Confirm with SurveyJS licensing before relying on this reading.
- **REDCap**: Likely already available through an NIH-funded institution; strongest on longitudinal/participant-list workflow and governance; but not self-hostable by you, no Docker/Python, and surveys are secondary to its data-capture role. Anonymous ID linking across waves requires designing a project with records keyed by your code.
- **KoboToolbox / ODK**: Field-data collection tools; good APIs and permissions but poor fit for rich free-text qualitative flows and wave linking.
- **Typebot/HeyForm/OpnForm**: Conversational/form builders; RBAC, token handling and licenses (FSL, AGPL+EE) mostly unverified. OhMyForm is archived.
- **SaaS (Qualtrics, SurveyMonkey, Typeform, Tally, Jotform, Alchemer, Google/MS Forms)**: No self-host; per-seat/response costs; group-owner multi-tenant RBAC only at enterprise tiers; data residency/DUA questions for NIH. Qualtrics "anonymize" disconnects response from contact, so use embedded data for your code instead (unverified).

## 3. Recommendation

**Adopt-first-pass: no tool meets all of {self-host, group-owner RBAC, token-linked waves, Python} out of the box.** Two viable paths:

| Option | Pros | Cons |
|---|---|---|
| A. Adopt LimeSurvey (self-host) | Free; tokens, free-text, API exist; fastest to pilot | PHP/MySQL ops; groups weak -> one instance per team or Superadmin does user mgmt; wave linking via shared token convention; JSON-RPC API |
| B. Thin custom layer: SurveyJS Form Library (MIT) + FastAPI + Postgres | Matches Python/uv/Postgres; you design exactly the model you need: `groups`, `memberships(role)`, `events`, `waves`, `participants(token, event_id)` (random, no PII), `responses(jsonb)`; no cookies by design (token in URL, no session for participants); clean export/ingest | You own RBAC, auth, survey authoring (build in JSON or buy Creator), security, a11y, maintenance. Estimated a few weeks for MVP (my estimate, not sourced) |
| C. Hybrid | SurveyJS Library + custom backend; skip Creator initially (hand-author JSON or use the free creator evaluation for design only, not production) | Authoring UX limited until Creator purchased (~$589 once) |

**Ranked shortlist**
1. **SurveyJS Library + FastAPI + Postgres (B/C)**: best fit to the stated constraints, esp. group-owner RBAC and token linking; buy Creator Basic only if non-developers must author.
2. **LimeSurvey self-hosted**: best off-the-shelf; use as stopgap/pilot or if build capacity is absent.
3. **REDCap** (if your institution offers it): strong governance and longitudinal; zero hosting for you; weakest on "own the stack/API ingestion by us".
4. **Formbricks**: only if budget for Enterprise key (RBAC) and heavy stack acceptable.
5. Qualtrics (if institution-licensed) as a non-self-host fallback.

Not recommended: OhMyForm (archived), Survey Solutions, Kobo/ODK (wrong use case), consumer SaaS tiers lacking group RBAC.
